# JoineryNest 木工榫卯与板材切割清单

基于 React、TypeScript、Vite、Chakra UI、Jotai、React Router 和 Canvas 构建。排料算法与
排料图渲染均为本地实现，项目数据自动保存在浏览器中。

## 功能

- 柜体与桌案零件建模：长、宽、厚、数量、板材和纹理方向
- 榫卯连接设计：燕尾榫、直榫、搭槽、圆木榫和饼干榫
- 按板材规格生成多张排料图，考虑锯缝、修边余量和纹理限制
- 利用率、废料面积、板材采购量和预计成本
- 在 Canvas 上拖动或输入坐标微调零件，并标记重叠风险
- 零件或连接修改后自动更新排料图和切割清单
- 项目文件保存 / 载入，零件表、排料图、用料说明和 SVG 导出

## 余料台账（可归属记录）

在「余料台账」页把开料后的余料流程接成可归属、可合并、可恢复的记录：

- **登记归属**：每块余料写入编号、长 / 宽 / 厚、板材、来源单号和登记班组（`src/domain/RemnantLedger.ts`）
- **占用先到先得**：两人同时占用同一块料，只接受先到的一笔；后来者被拒绝并提示改选别的料，已有占用归属不会被后写覆盖
- **增量失效**：改零件尺寸只重算放了该零件的排料图和对应成本，其余排料图沿用缓存；锯缝 / 修边 / 板材规格变化才整批重算（`src/domain/incrementalNesting.ts`）
- **断网合并**：断网时各写本机，回网按编号做三方合并（共同基线 + 甲 + 乙）；只有一边改的直接采纳（后传不盖先写），两边都改过则本机 / 对端各留一份进冲突清单，人工选定后编号仍唯一（`src/domain/sync.ts`）
- **失败恢复**：两阶段提交（后备暂存 → 主记录 → 提升后备），写入失败回滚到最近可用状态；主记录半截写坏时从已确认后备恢复，同一编号始终只有一条
- **余料位排队**：料位满时新登记先入 FIFO 队列，领用腾出位后自动放行

页面上可切换甲班 / 乙班、一键断网后两边各自操作再回网合并，并可「模拟下次写入失败」验证恢复。
